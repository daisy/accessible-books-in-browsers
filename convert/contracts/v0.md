# Web-book UI contract v0

A book stamped `<html data-webbook-contract="0">` guarantees everything listed here. A UI release
(the CSS and JS under `template/src/`, or a remote release on the `v0/` channel) may rely on
these and nothing else. Anything not listed must be feature-detected.

Compatible UI changes ship within the `v0` channel. A new incompatible contract requires
reconverting from the original EPUB; there is no webbook-upgrader. Keep the source EPUB.
Optional reader features must feature-detect their supporting files in older books.

`src/template-contract.ts` checks the converter's side: the hooks it fills in, and that the
template declares contract `0`.

## Scope note

New v0 conversions contain plain content and standalone navigation pages. Reader controls are
built by JS from the release's shell before feature initialization. Compatible control/styling
changes therefore do not require rewriting content. Earlier v0 books may contain embedded
chrome; release code feature-detects that shape and keeps it working. The detailed chrome hooks
below describe that legacy shape and the current reader's internal DOM, not requirements on
newly generated content pages. The authoring template still has converter hooks, validated by
`template-contract.ts`; those are separate from the delivered-content contract.

## Document

- One repaired content tree carries meaningful publisher styles as `webbook-style-*` classes
  and boxes as `webbook-box`; these add no semantics. Hidden/invisible/visible classes apply
  in both looks. Other reader classes and boxes apply only in the reader look.
- `data-webbook-has-published` on `<html>` identifies publisher CSS availability. The reader
  adds an "Appearance option" section before Colors: My settings (default) or As published, remembered
  for each book under `webbook-appearance:<book-id>` (`settings|published`, read in appearance.js;
  not in a settings file, cleared by Reset).
  With As published, the reader sets `data-webbook-appearance="published"`; without JS it is absent.
  `--no-publisher-styles` omits CSS and the availability attribute. There is no old-name compatibility.
- `link[rel="stylesheet"][data-webbook-publisher-style]` loads `styles/publisher-<content-hash>.css`.
  Identical sheets share a file. CSS is conditional on the appearance attribute, scoped to source
  publication elements and layered under `publisher` (source, inline, source-important,
  inline-important). Reader elements (`data-webbook-reader`, `.webbook` and its descendants)
  are excluded. Native SVG/MathML styles remain. Page navigation loads the next sheet while
  retaining the audio element. Root frame properties are omitted and renamed ids resolved.
- Converter-owned `webbook-publisher-r*` and `webbook-publisher-s*` freeze source selectors whose
  source target sets change, retaining specificity and dynamic states. Newly inserted reader
  elements never cause freezing. Temporary `data-webbook-publisher-source` identifies source
  elements during transformation and is removed before output. Converter wrappers are marked
  `data-webbook-reader` on the wrapper itself, allowing its publication descendants to be styled.
- `webbook-publisher-only` marks styled empty paragraphs hidden only in My settings; they add no
  narration/search text. `data-webbook-inline-style` identifies extracted inline declarations.
- Switching preserves the phrase or paused text position and uninterrupted audio. The remappable
  `switch-appearance` action defaults to Alt+Shift+D; its label is “Switch between As published
  and My settings”, and it announces the chosen look. The Appearance group has search keywords
  for the hidden preferences; hidden rows do not count as found.
- As published hides page/custom colors, font, size/reset, spacing, line length and Writing
  direction rows with `webbook-appearance-hidden`. Saved values return in My settings. One
  explanation in Appearance replaces the controls. Highlight, captions and other settings remain.
  There are no paused notes or descriptions. Reader settings are not translated from old look keys.
- CSS fonts/images are copied and URLs rewritten relative to the stylesheet. IDPF and Adobe
  font obfuscation is removed using the original package identifier; other encryption is skipped
  and reported. Reports count retained, frozen and unapplied selectors and copied assets.

- `<html lang="…" data-webbook-contract="0">`
- Optional writing attributes on `<html>` (plan 28), from the book's own CSS and package:
  - `data-webbook-writing-mode`: `vertical-rl` | `vertical-lr`, when the page's text is vertical
  - `data-webbook-line-break`: `strict` | `loose` | `anywhere`; `data-webbook-word-break`:
    `keep-all` | `break-all` (a language's line-breaking rules, for the whole page)
  - `data-webbook-page-progression="rtl"` when the spine's `page-progression-direction` is `rtl`
- `<head>`:
  - `<title>`
  - `<meta name="webbook-book-id" content="…">` (the book identifier; resume position is keyed on it)
  - The inline appearance script (below)
  - `<link rel="stylesheet" href="src/css/style.css">`
- `<script type="module" src="src/js/main.js">` at the end of `<body>`
- UI assets are at `src/css/` and `src/js/` relative to each page. In a converted book, `src/css/style.css`
  holds all the UI's CSS: the converter inlines the template's `@import`ed component files into it,
  in order, and leaves those files out. Pages are flat files in one
  directory (`index.html` is the entry page). The UI does not rely on any other asset path.
- `sw.js` at the book root, reserved for offline reading. Its content is fixed:
  `importScripts('src/js/offline-worker.js');` (plus a comment). Offline controls register it on
  first use, with explicit book-root scope and `updateViaCache: 'none'`. It is at
  the root because a service worker only controls pages at or below its own folder;
  `src/js/offline-worker.js` is UI and free to change.
- Optional `search-data.json` at the book root contains versioned book search data. If it's
  missing, the reader reports that search is unavailable rather than failing.
- `conversion-report.md` and `conversion-report.json` describe converter changes, warnings and
  requested optional checks. They are conversion records rather than reader dependencies.

### Offline reading (optional reader enhancement)

- `src/ui-files.json` is generated after combining CSS: `{ version: 1, contract: 0, revision,
  files: [{ href, bytes, sha256 }] }`. Files are every shipped file under `src/`, sorted in path
  order, excluding the inventory itself. URLs are relative to the book root, SHA-256 is lowercase
  hex, and revision hashes the UTF-8 `JSON.stringify(files)`. This includes lazy/vendor files.
  An older book can read normally without this file, but cannot claim a complete offline save.
  A complete local reader-package update supplies it without changing book HTML or root sw.js.
- `src/js/offline-worker.js` is a classic loader; the local implementation is
  `src/js/offline-worker-core.js`, with `offline-range.js` and `offline-network.js`. Long downloads
  run in the page-owned `offline-download-worker.js`, sharing the core through foreground mode,
  so they are not a single long-lived service-worker event. The fixed root stub is not rewritten.
  The compatibility bridge (not selected by the current reader, which requires local workers)
  allows worker script update URLs to carry validated `webbook-channel`/`webbook-worker` query values
  for an immutable channel release, while scope stays the same. An imported remote bundle must
  export `self.WebbookOfflineWorker = { protocol: 1, version, start }` without attaching handlers
  until `start()`. It can bundle `WebbookOfflineRange`; failed loads use the full local core,
  incompatible factories fail installation, and active readers are not forced through skipWaiting.
- UI/worker messages use a MessageChannel: `{ webbookOffline: 1, protocol: 1, command, ... }`.
  Commands are `status`, `saved-ui`, `begin-save`, `end-save`, `notify`, `cancel`, `remove`, `activate`;
  the SDK routes `save` through the foreground downloader (which accepts `save` and `cancel`); replies are `{ result }`, `{ error }`
  or intermediate `{ progress: { phase, done, total, bytes } }`. Calling clients must be content
  pages in this book's exact root, or a same-origin `src/offline-books.html` management page. No arbitrary worker URL is accepted in a message.
- `status` includes protocol/workerVersion/scope, `saved`, `complete`, `pending`, `pendingIncomplete`, `busy`, `recovering`.
  A snapshot contains cache name, files/validators/sizes, bytes, savedAt and `ui` descriptor.
  `save` receives a discovered file list (optional reusable Blob bodies) and `ui`:
  `{ contract: 0, localRevision, protocol: 1, remote?, localOnly? }`. A foreground lease records
  its owner client and staging cache, renews every 30 seconds and expires after 120 seconds or
  loss of the owner. Cancellation and commit check the lease transactionally. The page must stay
  open. Compatible remote factories accept `start({ scope, foreground })` as well as normal
  service-worker startup; `localOnly` selects the local download core. Every required UI hash and inventory
  entry is verified. Optional `remote` records a selected channel/version and the complete
  SHA-256 file inventory under its immutable releases/version directory, alongside local fallback.
  The remote bootstrap asks for the saved UI descriptor before selecting current.json.
- Cache Storage holds complete response bodies; IndexedDB `webbook-offline-1` stores `books`,
  `snapshots`, `pins`. Cache prefix `webbook-offline-1-<SHA256(root URL)>-` isolates copies even
  with identical EPUB identifiers. Pins keep an open client on its generation across worker
  restarts. An explicit `webbook-offline-recover=1` navigation selects a whole online recovery
  copy if required cached files are missing. Its query marker is removed after startup; a client
  pin keeps all subsequent resources online until a re-save is explicitly activated. Storage
  denial on an unsaved book falls through to ordinary network reading. Save/Update stages beside the working copy; `activate` requires other book tabs to
  close and is followed by an explicit reader reload. Unknown schemas are not cleared silently.
- Saved resources are cache-first both online and offline. Update discovery uses explicit
  same-book `X-Webbook-Offline-Network: 1` requests, including foreground GET/HEAD, to bypass the pinned content. No automatic
  reading cache, background download guarantee or required converter book manifest exists.
  Legacy update checks compare discovery and available HTTP validators; unreliable checks are
  labeled as such and allow an explicit full refresh. Generation integrity without publisher
  revision metadata has the limits described in the approved design note.
- Full 200 audio responses are saved deliberately. Cached range requests synthesize 206/416,
  with single closed/open/suffix ranges, If-Range and HEAD support. Multipart ranges use the full
  200 response. Partial/opaque/error responses never count as complete saved files.
- Offline state is not a preference and is neither exported/imported nor cleared by settings
  Reset. Remove clears only this book's caches and offline metadata, keeping reading preferences,
  Appearance, bookmarks and resume state. Browser eviction may remove both content and metadata.
- Created by UI: `section#webbook-offline` in About, its heading/status/storage text, labeled
  native progress/count, save/size/cancel/check/update/use/remove controls, inline Remove
  confirmation, and `button#webbook-offline-indicator` in the top toolbar while offline.
  Actions are registered with no default shortcut. New sections remain optional for old pages.

### Search data — `search-data.json` (optional)

Version 1 is `{ version: 1, lang, pages, passages }`. `pages` contains `{ href, title }` in spine
order. Each passage contains `{ page, heading, text, lang? }`; `page` indexes `pages`, and `lang`
is present only when it differs from the book language. A narrated passage has its cue's Web
Annotation selector (or an `id` when the cue target keeps one). A non-narrated passage instead has
`selector: { type: "TextQuoteSelector", exact, prefix?, suffix? }`. The browser builds its own
index from this data on first search and resolves selectors against `<main>`.

### Book audio map — `audio-map.json` (optional)

Version 1 is `{ version: 1, duration, pages, chapters }`. `duration` and all times are seconds.
`pages` contains every spine page as `{ href, title, start, duration, audio }`; unnarrated pages have a
zero duration and no `audio` (the page's narration file, relative to the book root). `chapters` contains ascending top-level TOC positions as `{ title, href, time }`. `toc` contains
every TOC entry, at every level and in TOC order, whose heading has narration, as `{ href, time, end }`:
the book time span that speaks the heading at that entry's target (the target, or the first heading
in it; without narration in a heading, the first phrase at or after the target). Its `href` matches
the TOC link's. Reserved for a talking TOC; nothing uses it yet.
When present, the UI enhances the per-page narration slider into a full-book timeline; without it
(no narration, or the map can't be fetched) the slider stays per page.

### Inline appearance script (frozen)

This runs before first paint and is baked into every page, so no release can change it. It reads:

| Key | Values | Effect |
|---|---|---|
| `webbook-appearance` | `auto` \| `dark` \| `light` | `webbook-dark` or `webbook-light` class on `<html>` |
| `webbook-font-size` | integer, clamped to 50–200 | `--webbook-main-font-size: N%` on `<html>` |
| `webbook-font-family` | `system-ui` \| `sans-serif` \| `serif` | `--webbook-main-font-family` on `<html>` |
| `webbook-caption-mode` | `'true'` | `webbook-caption-mode` class on `<html>` |
| `webbook-writing-mode` | `'horizontal'` | with `data-webbook-writing-mode` set and this key not `horizontal`: `webbook-vertical` class on `<html>` (and `webbook-vertical-lr` for `vertical-lr`) |

Releases must keep writing these keys with these meanings and value ranges, and CSS must honor
these classes and custom properties.

Caption mode is global. Both this script and the UI read the shared `webbook-caption-mode` key.
The former per-book caption and color keys are ignored; there is no migration of their values.

## Content (`<main>`)

- `<main>` holds the page's book content. It is the boundary for structure lookups. It has
  `id="webbook-main"`, the skip link's target.
- Source `xml:lang` is removed. Its value is copied to HTML `lang` only when most letters use the
  declared script; text with no letters and suspect values inherit their surrounding language.
  A tag whose expected script cannot be determined is copied.
- A repeated id stays only on its first element (links could only reach that one); a structure
  that loses it gets a generated id. Kept publication ids that collide with reader chrome get
  `-content` added, and internal links, navigation and narration selectors use the renamed target.
- Ids remain on structures and referenced elements. Structures include headings, document
  divisions, sidebars, figures, tables, lists, block quotes, notes, note references and print-page
  markers; the converter generates a stable page-local id for any such structure that lacks one.
  Original ids also remain when navigation, a link, an IDREF attribute, publication CSS, SVG or
  MathML references them. Ordinary narration phrases, paragraphs, table cells and inline elements
  do not keep otherwise-unused ids.
- Search does not add ids to non-narrated content; it locates those passages from text quote
  selectors at runtime.
- EPUB structural semantics appear as classes `epubtype_<type>` (`:` becomes `_`). The UI relies on:
  - `epubtype_pagebreak` (with `aria-label` holding the page label)
  - `epubtype_footnote`, `epubtype_endnote`, `epubtype_note`, `epubtype_sidebar`
  - `epubtype_table`, `epubtype_list`, `epubtype_figure`
- Plain `table`, `ol`, `ul`, `figure` elements are also treated as escapable structures, and so
  is MathML `math` (an equation narration reads on its own).
- A publication table is normally wrapped in
  `div.webbook-table-scroll[role=region][tabindex="0"]`. The wrapper is named by its caption's id,
  or by `aria-label="Table N"` when it has no caption. It has no id of its own. Reader JS removes
  `role`, `tabindex` and the ARIA name whenever the table fits, retaining the name in
  `data-webbook-label` or `data-webbook-labelledby`; it restores them when horizontal scrolling
  is needed. Without JS the labeled scroll region remains keyboard-operable.
- With markup cleanup enabled, title-only headings show their title as text; repeated titles
  are removed. Adjacent duplicate title-only headings leave the outline, with their link targets
  preserved if referenced. Empty headings get no generated permalink. Unlinked anchors that have
  no retained id or semantics are removed if empty, otherwise unwrapped. Empty nonsemantic
  `span` and `div` wrappers with only class/style/title attributes are removed too. Narration selectors are
  generated after this final cleanup; narrated target elements themselves are preserved.
- A numbered equation is a block marked `webbook-equation`, containing one MathML expression
  (possibly inside neutral wrappers) and a short number marked `webbook-equation-number`.
  The expression branch is wrapped in `span.webbook-equation-scroll[role=region][tabindex="0"]`,
  named with `aria-label="Equation (1.1)"` using its actual number. DOM order and MathML are kept.
  CSS centers the expression and puts the number at the logical line end, below at narrow widths.
  Reader JS uses `data-webbook-equation-stacked` when an expression needs the full line and keeps
  the named region/tab stop only while it scrolls (the name is retained in
  `data-webbook-equation-label`). The wrapper still scrolls without JS.
- Inline MathML wider than its line scrolls within its available width: reader JS marks it
  `data-webbook-math-wide` (which gives it `overflow-x: auto`) and adds a temporary Tab stop,
  preserving native math semantics and restoring the original focus hook from
  `data-webbook-math-tabindex` when it fits. Other inline MathML doesn't scroll, so glyphs taller
  than the line add no Tab stop. Without JS, wide inline MathML overflows its line. Display
  equations use their outer scroll wrapper.
- Chapter cuts move outside indivisible headings, paragraphs, list items, tables, figures,
  definition items and blockquotes, even with markup cleanup disabled. Multiple TOC targets inside
  one such block share a page; their target ids remain addressable.
- Heading self-links: `h* > a.webbook[rel=bookmark][href="#<heading id>"]`.
- `dir` from the source `<html>` or `<body>` is on `<main>` (the book's text; the reader's own
  controls keep theirs).
- The book's writing styles (plan 28) are classes on the elements the book styled, read from its
  cascade (`-epub-`, `-webkit-` and standard spellings), only where an element's value differs
  from what it inherits; a page-wide one is on `<main>`. The UI styles them in standard CSS:
  `webbook-style-combine` and `-combine-none` (`text-combine-upright`);
  `webbook-style-glyphs-upright`, `-sideways`, `-mixed` (`text-orientation`);
  `webbook-style-horizontal`, `-vertical-rl`, `-vertical-lr` (`writing-mode`);
  `webbook-style-emphasis-<shape>[-open]` for `dot`, `circle`, `double-circle`, `triangle`,
  `sesame`, and `-filled`, `-open`, `-none` (`text-emphasis-style`, in the text color);
  `webbook-style-emphasis-over`, `-under`, `-left`, `-under-left` (`text-emphasis-position`);
  `webbook-style-fullwidth` (`text-transform: full-width`); `webbook-speak-spell-out`, `-digits`,
  `-literal-punctuation`, `-no-punctuation` (`speak-as`, hints only).
- Entry page only: `section.webbook-title-page` with `img.webbook-title-cover`, `.webbook-title-kicker`.

## Narration

- Optional. On a page with narration there is a single `<audio>` in `#webbook-toolbar` with `src`
  or `source[src]`. On a page without narration the converter removes `<audio>`,
  `#webbook-narration-position` and `#webbook-audio-controls`.
- The converter cuts SMIL clips to PCM, joins them, and encodes each page once. By default it
  writes mono, 24 kHz MP3 at 32 kb/s, tuned for speech-sized downloads. With `--no-small-audio` it
  keeps the source's format instead, with the highest channel count, sample rate and bitrate among
  that page's sources (MP3 sources produce MP3 without an intermediate lossy encode).
- Unless `--no-audio-cleanup` is used, clips have short fades at joins and each joined page is
  low-cut filtered (rumble), de-plosived and normalized with a two-pass loudness measurement. The enhancement
  filters (all five by default; `--audio-enhance` chooses) do not change the page or cue duration.
- One `<track>` child: WebVTT metadata. Each cue's text is JSON containing a Web Annotation
  selector. It is a `FragmentSelector` when the phrase itself has a retained id; otherwise it is a
  structure's `FragmentSelector` with a scoped `CssSelector` in `refinedBy`, or a main-relative
  `CssSelector` when no anchoring structure exists. The UI resolves and caches every cue element as soon as the track loads, before any
  feature changes the publication DOM.
- Cues are in document order.

## Chrome

All IDs below are present on every page unless marked optional.

The chrome is in the order it appears on screen, so Tab follows it: the skip link, the top toolbar,
`<main>`, spine navigation, then the bottom toolbar.

### Skip link — `a#webbook-skip-link.webbook` (optional)

- First in `<body>`, `href="#webbook-main"`, text "Skip to text". The UI handles it: focus goes to
  the reading position (the phrase being read aloud, else the phrase or structure at the reading
  line). `#webbook-main` doesn't go into the URL or move the narration.

### Spine navigation — `nav#webbook-spine-nav`

- `a#webbook-previous-document`: has `href` when a previous page exists. On the entry page it is
  removed (converter output) or has no `href` (hand-authored template). The UI treats "no
  `#webbook-previous-document[href]`" as "this is the entry page."
- `a#webbook-next-document[rel=next]`: has `href` when a next page exists; removed otherwise.
- The UI looks up spine links as `#webbook-spine-nav a[rel=next|prev][href]`.

### Basic navigation (optional) — `nav#webbook-basic-nav`

For reading without JavaScript, the first element in `<body>`: a `button[popovertarget="webbook-toc-nav"]`
("Contents"), and `a#webbook-basic-previous[rel=prev]` and `a#webbook-basic-next[rel=next]` with
the page titles as text (removed when there's no such page). The TOC has a
`button.webbook-basic-close[popovertarget="webbook-toc-nav"][popovertargetaction=hide]`. The
toolbar's `<audio>` has `controls`. CSS hides all of these, and shows the toolbars, when `<html>`
has `webbook-dark`, `webbook-light` or `webbook-js`, i.e. when the reader's script runs; without
it, CSS hides the toolbars except the `<audio>`, which shows the browser's player.

### Table of contents — `nav#webbook-toc-nav[popover].webbook`

- `h2#webbook-toc-nav-hd`; optional `a#webbook-cover-link` points to the cover document identified
  by EPUB landmarks or the EPUB 2 guide (it is omitted when the EPUB identifies only a cover image).
  The UI moves this link to the About panel.
- Nested `ol > li > a`. The link for the current page has `aria-current="page"`, but only when a
  link points at the page itself: when every link to a page has a `#fragment`, none is marked. The
  UI marks the entry for the reader's section itself when the TOC or About panel opens.
- In a book narrated in part (some TOC links lead to narrated pages, some don't), each link to a
  narrated page has `data-webbook-narrated` and ends with `span.webbook-narrated-mark` (an
  `aria-hidden` icon and `.sr-only` text ", narrated"). A `p#webbook-toc-narration-key[aria-hidden]`
  before the list explains the icon. A fully narrated or unnarrated book has none of these.

## Created by the UI (not part of the contract)

The JS creates these, so a release may change them freely:

- `.webbook-popover-close` buttons in each popover
- `section#webbook-caption-view` with `#webbook-caption-text`; caption text preserves note-reference
  numbers as `<sup>` without adding brackets or copying links, ids or publication styles
- The keyboard shortcuts setting (`#webbook-keyboard-shortcuts-toggle` and its row), added to the
  Keyboard section if the page doesn't already have it
- The "Change keyboard shortcuts" button below that row and
  `section#webbook-keyboard-shortcuts[popover]`, a separate panel with grouped action lists,
  current keys, Change/Remove controls, an individual Restore default control for changed bindings,

### Copying equations and code

The reader also creates equation/code Copy controls (not publication contract ids):
`span.webbook-copy-unit` around display MathML, or `div.webbook-copy-unit.webbook-copy-code`
around a `pre`, with a button after the source, never inside a code listing. MathML includes
`math[display=block]`, `.webbook-equation math`, `.disp-formula math`, and an expression that is the only content of its
block. Wrapping and focus hooks are added only after narration cue elements are resolved.
Inline math has no Copy button; `tabindex=-1` permits screen reader focus, with a temporary
Tab stop when the expression needs keyboard scrolling.
An overflowing display equation or code listing gets a temporary Tab stop for keyboard scrolling;
it is removed when the source fits again. Copy controls add no text to a narrated phrase's
`textContent`.
Copy equation, Copy selection and Copy code are reader actions registered without default keys
(no menu: selecting text and the browser's own Copy covers inline math). Controls are hidden without a secure context and Clipboard API. The Text section creates
`select#webbook-copy-math-options`; `webbook-copy-math-format` stores `mathml` (default) or `latex`
and participates in settings export/import/reset.

Equation clipboard payloads include MathML in `text/html`, with reader attributes removed, and
LaTeX or MathML in `text/plain`. LaTeX uses a non-empty `annotation[encoding=application/x-tex]`,
then non-empty `alttext`, then lazy reader-side conversion; failure preserves complete MathML.
Text selections containing math keep complete expressions in HTML and use `$…$` around LaTeX.
Code is plain text from `pre.textContent`, without buttons. Conversion preserves MathML fallback
images by copying/rewriting `math[altimg]` through the image registry. `alttext` stays as the book
has it, empty or not; no alternatives or TeX are added to publication content.

The vendored converter is mathml-to-latex 1.8.0 (MIT), 169,560 bytes with its license and native
DOMParser adaptation, 36,975 bytes gzipped. It loads on the first copy that needs conversion.

### Settings file

Other tools may use this versioned format. Export downloads `webbook-settings.json`:

```json
{
  "format": "webbook-settings",
  "version": 1,
  "exported": "2026-11-10T12:00:00.000Z",
  "settings": { "webbook-colors": "sepia", "webbook-font-size": null }
}
```

`settings` maps the preference keys in `settings-file.js` to localStorage strings or `null` (unset,
use the default). Export includes every registered key; shortcut mappings retain their JSON string
representation. Reading positions, one-shot navigation flags and tab state are excluded. Import
validates the complete file before writing: wrong formats, unsupported versions and invalid known
values are rejected; unknown keys are ignored, missing keys retain their current values, and `null`
removes a preference. Import and reset reload the current page while keeping its position and
narration time. Reset removes only registered preference keys. The UI's sections, jump links,
transfer buttons and two-press reset confirmation are not publication contract ids. The three
transfer actions (`export-settings`, `import-settings`, `reset-settings`) have no default shortcuts
and can be assigned in the shortcut editor.

### Agent tools

When enabled and the browser implements WebMCP, the UI registers these stable imperative tools on
`document.modelContext` (with the older `navigator.modelContext` as a fallback): `reader_status`,
`list_contents`, `go_to`, `narration`, `set_reading_option`, `search_book`, and `read_text`.
Registration is progressive enhancement and failures do not affect reading. Turning the global
setting off aborts all registrations. Search results and returned publication text carry WebMCP's
untrusted-content annotation; no tool exposes state from another book or arbitrary storage.

## URLs

- A generated page may represent one chapter of a larger EPUB content document; element ids remain
  unique across all generated pages in the book.
- `#<id>` in the page URL names the nearest retained structure at or above the reading position.
  In a narrated book, `?t=<seconds>#<id>` refines that structure to an exact cue; opening it seeks
  and scrolls to that phrase. Without script the hash still reaches the structure. During narration, after paused scrolling, and when focus moves in
  the text, the UI updates the URL with `history.replaceState`, retaining `history.state` and never
  creating a history entry. An explicit hash or `t` takes precedence over a saved resume position.
- The UI may load another page of the book in place instead of navigating to it: it fetches the
  page, swaps in its `<main>`, `<title>`, `lang`, spine links, TOC `aria-current` and narration,
  and sets the page's URL with `history.pushState`. It does this only for a page in the same
  directory with the same contract, book ID and stylesheets, and loads anything else normally. So
  every page must still work as a complete page on its own, and the URL in the address bar is
  always a real page.
- Page identity, in-place navigation and cross-page autoplay comparisons ignore `t` and other
  query parameters; Back and Forward continue to use their saved exact scroll and audio state.

The saved-books management page is `src/offline-books.html`, linked from About. It reads the
same-origin offline database and sends per-book operations to each existing registered worker.
Refresh uses that book’s foreground lease and stages an update; activation remains explicit and
requires other book tabs to close. Removal keeps preferences. A `webbook-offline-library-` cache
retains the hosting reader’s `src/` files so the management page can reopen after all books are
removed; it contains no publication text/audio/images. The root worker serves this shell only
for the management page and its subresources when the hosting book has no active snapshot.

## Remote delivery and plain book shape (bootstrap API 1)

- New content pages have `data-webbook-shell="1"`, `<main>`, a skip link, real links in
  `#webbook-basic-nav`, previous/next links, native narration in `#webbook-toolbar`, and permanent
  `#webbook-escape-status` / `#webbook-resume-banner` live regions. Reader controls are absent.
- `toc.html` and `about.html` are standalone, script-free navigation documents; `pages.html`
  exists only with print-page links. These filenames are reserved; conflicting source chapters
  are renamed and mapped like any other output filename. The content page's Contents fragment
  identifies its entry. `data-webbook-navigation` identifies navigation pages.
- `webbook-page-file`, `webbook-page-number`, `webbook-page-count`, `webbook-page-label` metadata
  supply current-page identity/progress. `webbook-source` is JSON with original source filename,
  EPUB identifier (independent of a reader-ID override), and converter package version. About
  attributes original EPUB claims to their source and retains its complete metadata XML/roles.
- Local styles carry `data-webbook-local-style`. Remote styles carry `data-webbook-ui-style` and
  are excluded from content-page stylesheet comparisons. UI resources never resolve against
  `import.meta.url`; content/navigation paths resolve against the book. `src/reader-shell.html`
  belongs to the local reader inventory; release main.js embeds its own shell.
- Channel-enabled `webbook-ui-channel` metadata contains the HTTPS channel directory (localhost HTTP is
  allowed for tests). The default beta channel is
  `https://daisy.github.io/accessible-books-in-browsers/v0/`. Conversions default to the channel with a prominent notice;
  `--no-remote-ui` selects a fixed bundled copy and omits the metadata. Channel-enabled pages set `no-referrer` and preconnect to the channel origin.
- The inline bootstrap is a prebuilt readable API-1 bundle, with an identical external same-origin copy at `src/js/bootstrap.js` for
  CSPs blocking inline scripts. Both share a startup guard. `main.js` exports async `init()`;
  it must not mutate reader state at import time. Pure policy in `bootstrap-policy.js` is unit-tested
  and compiled with `bootstrap-source.js` by `build-bootstrap.mjs`; conversions copy that reviewed
  bundle without importing a Node bundler (the browser converter shares this path). `webbook-js` identifies enhanced mode; the
  baseline remains readable without it, including file URLs and clean reloads after failure.
- `current.json`: `{contract:0,version,minBootstrap:1,script,stylesheet,worker?,inventory,protocol:1}`.
  Relative resource paths must stay inside that version's `releases/<version>/` directory.
  Every remote selection requires script/style hashes from its immutable inventory, or stored
  verified inventory for a saved selection. Missing hashes select local UI. Optional manifest
  `integrity:{script,stylesheet}` fields must agree with that inventory. CSS always uses SRI; JS
  bytes are always verified before importing a module Blob URL. Restrictive CSPs select local UI.
  `{contract:0,useLocal:true}` is the kill switch. Invalid, timed-out, CORS-blocked or incompatible
  releases select both local CSS/JS. CSS remains inactive until the matching module downloads.
- Bootstrap first consults the worker's saved UI. `saved-ui` returns `{ui,recovering}` without
  scanning content caches; older workers are queried for status. Unknown saved state selects
  local fallback. Default channel state cannot replace a saved release; testing overrides can
  select an uncached release online without rewriting the snapshot.
- Unsaved books use a cached good manifest immediately and refresh it with a 1.5-second bound
  for the next page view. No cached manifest waits at most that long. Asset downloads/startup
  are bounded; failed imports fall back on the same page before init. Startup crashes reload
  cleanly: remote → local → baseline. Failure flags and URL fallbacks prevent reload loops when
  storage is blocked. Bad remote releases are remembered by version.
- `?webbook-ui=local|remote|release:<version>|auto` persists valid choices then removes the
  parameter. Local override is in localStorage, testing overrides in sessionStorage. Keys use
  `webbook-ui:<book-root>:override`; manifests, bad-version flags and reload guards use the same
  book-root prefix. Auto clears overrides and baseline/retry guards. Source documents never
  contain a reader's override. `window.webbookUI` exposes the selected validated descriptor to
  the current reader's offline controller. About shows any stored override and offers Return to
  automatic updates, preserving reading position; this also clears internal URL crash guards.
- Remote saved descriptors retain complete immutable release files plus the local fallback.
  Update discovery validates a fresh channel inventory; activation is explicit. Executable service
  and download workers remain local (`localOnly:true` even with a remote page UI), because classic
  importScripts cannot verify integrity before execution. The remote worker bundle is retained
  and checked as an asset but not executed by this reader. The optional old bridge is compatibility
  tooling only. No forced skipWaiting or schema-clearing occurs. Root sw.js is byte-for-byte unchanged.
